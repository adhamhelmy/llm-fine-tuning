# Response to the reviewers (draft)

We thank the reviewers for this comment, which we found justified. Our original manuscript went
straight to loop engineering (GRPO) on top of one untuned zero-shot prompt with no context. It
therefore could not separate what RL contributes from what a better prompt, context or harness would
have achieved. We have rewritten the methodology around the LLM-engineering ladder and re-run the
experiments accordingly.

**Comment:** *"The methodology needs to be rewritten in the scope of the LLM engineering ladder:
prompt, context, harness, loop, and graph engineering, with details at each stage."*

Section 3 now has one subsection per stage (§3.3–3.7). Each subsection states:
1. the design and its rationale;
2. the exact variants tested (Table 1);
3. the results with 95% CIs and paired significance tests (Table 2).

All prompts are reproduced verbatim in Appendix A. They are generated by the same code that runs the
experiments, so the appendix matches the prompts actually sent to the models.

**Comment:** *"Which prompts were used and how good are they?"*

- **Which prompts:** Appendix A gives the baseline prompt and every variant: compact, few-shot,
  plan-then-code, and each context block. §3.3 explains what failure mode each of the ten rules in
  the baseline prompt addresses.
- **How good:** Table 2 (prompt block) reports every variant's valid, traded, profitable and
  beats-buy-and-hold rates, compared against the baseline prompt. The best variant is selected on a
  separate dev period and only then evaluated on the held-out test period. **[Summarize the result,
  e.g. "few-shot examples raised the valid rate from X% to Y% (p = …)".]**

**Comment:** *"Maybe with better prompts and better context, like financial RAG, the results could
be completely different."*

We agree this had to be tested, and we now do (§3.4). There are three kinds of context:
1. an automatically generated Backtrader API reference;
2. statistics of the stock computed strictly before the backtest window;
3. a financial RAG component: BM25 retrieval over a strategy-knowledge corpus, queried with the
   stock's market regime.

We also added harness-level error repair (§3.5), inference-time refinement (§3.6.1) and a two-agent
analyst → coder graph (§3.7). Two design points matter here:
- **No test leakage.** All feedback and context is restricted to data from before the evaluated
  window.
- **Memorization.** We add a memorization probe with the ticker and dates hidden, because an LLM
  could otherwise draw on remembered price history.

**[Report the outcome honestly. If context/harness closed most of the gap, say so, and reframe
RL's contribution as the increment on top of it.]**

**Comment:** *"If the paper is at the loop-engineering stage via RL, we need to ensure the prompt and
context steps are done correctly and give the best results before going to loop engineering."*

The protocol now enforces this ordering.
- **Greedy stage-wise selection:** each stage is optimized on the dev period on top of the best
  configuration of the stages below it (§3.2).
- **GRPO training uses the selected prompt and context** (§3.6.2).
- **The RL model is compared with its base model at the same, best, rung** (Table 3), so the reported
  RL gain is the improvement *beyond* the best prompt, context and harness configuration.

**Additional changes prompted by the review**

- **Non-overlapping train / dev / test periods.** The original windows were inconsistent across
  experiments:
  - Colab GRPO training used 2012–2021 and the model comparison tested on 2022 onward, which is
    clean.
  - The Kaggle training run used 2016–2024, overlapping that test period.
  - The single-model sampling results were evaluated on 2016–2024, overlapping training.

  We now use one fixed split everywhere: train 2016–2019, dev 2020–2021, test 2022–2024 (§3.2).
  **[State which of the original numbers are affected.]**
- **More samples and proper statistics.** Previously we had 20 samples per model and reported point
  estimates. We now use 150 samples per rung on test, with Wilson and bootstrap CIs and paired,
  symbol-level bootstrap tests.
- **Baselines.** Buy-and-hold and an SMA 50/200 crossover are reported alongside every
  configuration, and "beats buy-and-hold" is now a primary metric.
- **GRPO group size.** **[If changed:]** We increased the number of generations per prompt from 2 to
  G = … . Two samples give a very noisy group-relative advantage.
